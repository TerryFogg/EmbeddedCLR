# ESP-IDF sdkconfig Workflow

The recommended approach is to let ESP-IDF generate a complete configuration first, then maintain a small override file containing only project-specific settings.

## 1. Generate a Baseline Configuration

Call `idf_build_process()` with minimal inputs:

```cmake
idf_build_process(
    esp32p4
)
```

ESP-IDF will generate a complete `sdkconfig` file in your project root directory  using:

- Target defaults
- Component defaults
- Kconfig dependency resolution

This generated file contains the full resolved configuration used by the build.

---

## 2. Review the Generated sdkconfig

The generated `sdkconfig` becomes the reference for available options.

Examples:

```text
CONFIG_ESP32P4_REV_MIN=1
CONFIG_SPIRAM=y
CONFIG_SPIRAM_MODE_OCT=y
CONFIG_FREERTOS_HZ=1000
```

This file may contain thousands of entries.

---

## 3. Create a Project Override File

Create a file such as:

```text
sdkconfig.esp32p4
```

containing only the settings that should be explicitly controlled by the project.

Example:

```text
CONFIG_ESP32P4_REV_MIN=1

CONFIG_SPIRAM=y
CONFIG_SPIRAM_MODE_OCT=y

CONFIG_FREERTOS_HZ=1000
```

Avoid copying the entire generated `sdkconfig`.

---

## 4. Use the Override File

Pass the override file as an input to `idf_build_process()`:

```cmake
idf_build_process(
    esp32p4
    SDKCONFIG_DEFAULTS
        ${CMAKE_SOURCE_DIR}/sdkconfig.esp32p4
)
```

ESP-IDF will:

1. Load target defaults.
2. Apply project overrides.
3. Resolve dependencies.
4. Generate a new complete `sdkconfig`.

---

## 5. Treat Files Differently

### Generated File

```text
sdkconfig
```

- Generated by ESP-IDF
- Do not edit manually
- Can be regenerated at any time

### Project Configuration

```text
sdkconfig.esp32p4
```

- Maintained in source control
- Contains only intentional overrides
- Documents project requirements

---

## ESP32-P4 Recommendations

For ESP32-P4 Rev 1.3 hardware:

```text
CONFIG_ESP32P4_REV_MIN=1
```

For boards with PSRAM:

```text
CONFIG_SPIRAM=y
```

Let ESP-IDF derive all dependent options whenever possible.

---

## General Rule

Only specify settings that are:

- Hardware-specific
- Feature-specific
- Required by the application

#### Usually don't touch the following entries, they usually describe the Chip
CONFIG_SOC_*

CONFIG_IDF_TARGET_*

CONFIG_ESP_ROM_*

#### Usually do tune the following, they conhtrol features and code generation
CONFIG_SPIRAM
CONFIG_FREERTOS_*
CONFIG_LWIP_*
CONFIG_MBEDTLS_*
CONFIG_BT_*
CONFIG_WIFI_*
CONFIG_FATFS_*
CONFIG_LITTLEFS_*

#### Code size is affected by components, but some components have dependencides that will load other components

 For example
 ```
idf_build_process(  esp32p4
                    COMPONENTS
                      freertos
                      esp_timer
)
```
Does not mean only two components are used, ESP-IDF will automatically pull in dependencies such as:
```
soc
hal
esp_hw_support
esp_system
newlib
riscv
```
#### To list all components that will be used, run the following command in the build directory:
```
idf_build_get_property(BUILD_COMPONENTS BUILD_COMPONENTS)

foreach(c ${BUILD_COMPONENTS})
    message(STATUS "${c}")
endforeach()
```
